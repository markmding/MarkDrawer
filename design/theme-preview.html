12 篇 · 附件同步

记笔记这件小事

一份好看的默认主题，应该让人打开就愿意写。它需要安静的底色、清楚的字号层级，以及只在需要时才出现的 accent。

为什么从配色开始

长时间阅读时，正文与底色的对比度决定了眼睛累不累；而链接、行内代码和引用这类元素，需要和正文拉开细微但明确的区别。

  • 背景不纯白，减少屏幕刺眼感
  • 正文对比度控制在 6–12 之间
  • 强调色只用于可交互元素
好的主题不抢戏：写的时候忘记它的存在，截屏的时候又觉得体面。
提示
把配色变量集中在一处，明暗切换只换变量，不改组件样式。

代码块与表格

// 主题变量示例
const theme = {
  bg: '#282c34',
  text: '#abb2bf',
  accent: '#61afef',
  apply(el) { el.setProperty('--bg', this.bg) }
}
元素建议取值
正文不纯黑#abb2bf
边框低对比#3a3f4b
强调蓝 / 青#61afef

最后一行，用来确认行距和段落间距读起来是否舒服。

界面与正文色卡

怎么选：想要稳妥、耐看、和现有灰蓝气质接近 → One；想要更现代柔和、浅色偏米 → Catppuccin；喜欢暖色和个人风格 → Monokai Pro；强调“像一个正经工具” → GitHub。Nord 与 Material 更偏冷，适合长时间写代码笔记。

色卡变量名对应 src/app.css 的 --bg / --bg-subtle / --text / --border / --accent …，导出侧对应 src/lib/export/themes.ts 的 --mk-*。选定后我按这套色卡改内置明暗主题。
